# Reflection

原生 Windows 角色对话与本地阅读应用，基于 C#、.NET 10 和 WPF。连接已运行的本机推理服务，支持独立会话、角色卡、Markdown / TXT 阅读，以及内容隔离的日常与隐私工作区。不内置浏览器、Node 后端或模型运行时。

项目原创内容采用 [MIT 许可证](LICENSE)。第三方代码、字体及具有独立许可声明的资源保留各自许可，详见 `third-party`；发布时同时保留项目 LICENSE 和第三方许可文件。

## 运行

唯一正式版本位于 `artifacts/Reflection-latest`。安装 **.NET 10 Desktop Runtime** 后运行其中的 `Reflection.Desktop.exe`，分发时保留整个目录。当前无安装器、签名和自动更新。

1. 启动本机推理服务并准备模型。
2. 点击侧栏底部设置图标，添加地址与协议并检测。
3. 从角色详情开始对话，或直接新建对话并选择模型。

「新建对话」从空角色开始。通过角色详情发起的对话会在角色消息左侧显示头像与名称。可在角色编辑器中选择头像文件，或在封面原图上重新选择圆形头像区域。

默认点击标题栏关闭按钮或按 Alt+F4 会收起到 Windows 托盘，正在生成的回复和图片处理继续运行。左键单击托盘图标可恢复原窗口，右键选择「退出 Reflection」可保存并彻底退出。可在「设置 → 窗口行为」关闭托盘驻留，此后关闭窗口会直接退出应用。

默认配置 Ollama `http://127.0.0.1:11434`。不扫描端口，不下载模型，不自动安装或启动推理服务。

| 协议 | 模型列表 | 流式生成 |
| --- | --- | --- |
| Ollama | `/api/tags` | `/api/chat`，NDJSON |
| OpenAI 兼容 | `/v1/models` | `/v1/chat/completions`，SSE |

地址接受根路径或 `/v1`，仅允许回环 HTTP(S)，拒绝内嵌凭据，禁用代理和自动重定向。暂不支持 API Key。模拟协议测试不代表所有真实服务均兼容。

llama.cpp 公布模型支持的推理档位时，界面的低、中、高优先匹配同名档位，其余按模型公布的顺序映射。例如模型只提供 `low`、`medium`、`xhigh` 时，高档会发送 `xhigh`。路由模式的未加载模型会沿用服务端默认档位，模型加载后再探测。

## 当前功能

- **对话**：多会话独立后台生成、停止、重新生成、接着写、辅助起草、用户消息编辑重发、思考折叠、Markdown 导出；历史支持搜索、改名、删除与折叠。
- **角色**：随窗口变化的虚拟画廊、详情、窗口内创建和编辑、JSON Character Card V1/V2 基础字段导入导出、3:4 图片裁剪。角色设定同步关联会话，已有开场白作为历史保留。角色库写入失败保留原状态和编辑草稿，关联会话同步失败单独提示并可重试。
- **阅读**：原生 Markdown / TXT、多来源书库、按需展开目录、已加载文件名筛选、章节目录、字号 / 行距 / 行宽 / 字体设置、专注模式、阅读锚点及可选最近文档快照恢复。Markdown 的六级标题各有字号，标题与正文之间的留白随行距缩放，无序列表按层级切换符号。正文选区跟随深浅主题。默认过滤点号名称、Hidden/System 项。
- **排版**：聊天与阅读共用六级标题、多级列表和任务框、引用、表格、脚注跳转、定义列表、上下标及 GitHub 提示块。代码块有行号，C/C++、C#、Java、JavaScript/TypeScript、Python、Shell、JSON 和 SQL 等常用语言有基础高亮。数学支持 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`，可离线显示比较符、伸缩括号、分式样式、带标注箭头、多行对齐、公式编号与引用，以及常用化学和物理记号。代码和金额受保护，不支持或超限的公式显示源码。复制消息与导出保留原始 Markdown / TeX。
- **附件**：文本文件、图片文件 / 拖放 / 剪贴板；单条输入最多四张图片（含处理中），原图保留，模型输入长边不超过 1280；JPEG 使用有损压缩，PNG 等格式保留透明与清晰边缘。后台处理并复用缩略图和派生图，角色图片可基于原图重新裁剪。消息图片右键可再次引用；文件和文件夹浏览使用系统对话框。
- **工作区**：日常与隐私的聊天、角色、草稿、书库、阅读位置和工作区偏好独立保存，关闭窗口的行为由两个模式共用。切换复用原窗口，服务检测在后台进行。启动默认日常模式的角色页。
- **界面**：暖白 / 暖炭主题、紧凑页头、窄窗口侧栏抽屉、悬停消息操作；底部依次为模式、主题、设置三个图标。空心盾牌表示日常，带勾盾牌表示隐私。

阅读页右侧工具栏提供字号与排版、目录。可按 F11 切换专注模式，按 Ctrl+O 打开文件，阅读空白页也提供打开文件入口。

## 数据与限制

默认目录 `%LOCALAPPDATA%\Reflection`，可用 `REFLECTION_DATA_DIR` 覆盖。日常数据位于根目录，隐私数据位于 `private` 子目录。首次进入隐私模式只沿用连接与主题默认值，不复制内容。

**隐私模式提供内容隔离，仍为本机明文持久化，没有加密、密码或退出自动擦除。** 聊天、图片、草稿、思考、阅读快照和备份均在此范围。应用无遥测，只向配置的本机端点请求；推理服务自身是否联网由该服务决定。

存储使用 JSON、临时文件与 `.bak`，支持备份恢复和索引重建。图片按内容哈希存入各工作区的 `assets/images`，JSON 保存引用；移动或备份数据时需保留整个工作区目录。旧内嵌图片在保存独立快照时渐进迁移，旧备份仍可读取。删除会话同步清理正文、备份及索引摘要，不承诺物理安全擦除。导出文件和剪贴板不受应用删除控制。资产清理保留正文、草稿、角色快照及备份仍引用的图片；遇到损坏数据时跳过清理。角色卡 JSON 导出内嵌当前封面和头像派生图。

请求同时按文字、图片数量和编码体积预算保留最近完整轮次。较早的图片及所在轮次超限时退出本轮上下文并提示，历史记录保持完整；本次图片自身超限才拒绝发送。客户端缓存不保证推理服务复用视觉特征。

模型选择框右侧显示当前会话最近一次成功回复的生成速度与小型上下文圆环。速度优先使用服务端统计，带「≈」的速度按实际输出 token 和客户端请求耗时估算。悬停圆环可查看占用百分比和 token 用量，点击可修改本对话的上下文长度，留空使用模型服务默认值。本机上下文字符预算用于发送前裁剪历史，实际 token 容量由推理服务决定。指标只保存在当前运行的工作区内，自定义长度随会话保存。

阅读器显示 Markdown 引用的本地位图，相对路径以文档所在目录为准。图片按可用行宽缩放。远程图片显示替代文字，点击后可在浏览器中打开。缺失或无法解码的本地图片保留替代文字。阅读器支持 `[[文件#章节|显示文字]]`，文件路径以当前文档为基准，省略扩展名时使用 `.md`。

`mermaid` 代码块可离线显示基础无环流程图和时序图，`plantuml` / `puml` 可显示基础时序图。流程图支持常见箭头、方框、圆角框和菱形判断，时序图支持参与者、别名及消息箭头。复杂语法和超限图表保留带行号的源码。原始 HTML 保持文本显示，SVG 与自定义或外部 TeX 暂无预览。

公式内的中文可用 `\text{中文}`，字形来自 Windows 已安装的字体。公式编号按当前文档的源码顺序计算，`\eqref` 和 `\ref` 可引用同一文档后面的公式。`\SI{数值}{单位}` 和两组参数的 `\qty` 支持常用 SI 单位、前缀与幂次，保留超出该语法范围的源码。

停止、失败及未完成回复不会自动进入下一轮上下文；明确续写时使用原回答快照。数学排版不是完整 TeX 引擎，跨公式拖选复制尚不保证完整，请用消息复制按钮。阅读不执行 HTML / 脚本，不自动加载远程图片，全文搜索暂未实现。

## 开发与验证

需要 .NET 10 SDK；桌面冒烟测试还需 Python 3，仅使用标准库。

```powershell
.\scripts\build.ps1                 # Release 构建
.\scripts\build.ps1 -Test           # 核心与真实 WPF 冒烟
.\scripts\build.ps1 -Publish        # 更新唯一正式版本
python scripts/smoke.py --workspace-only  # 已构建后单测模式隔离
python scripts/smoke.py --tray-only       # 已构建后单测托盘
```

发布前彻底退出应用以避免文件占用。开启托盘驻留时，可使用托盘菜单的「退出 Reflection」。发布只输出 `artifacts/Reflection-latest`，同步三份项目文档及第三方许可，不另留 ZIP 或备用版本。测试按需生成 `artifacts/smoke-*`，构建缓存及测试结果可重建。

2026-11-11 回归通过，包括 78 项核心测试、四组 WPF 桌面流程、工作区隔离和托盘回归。公式回归在 Markdown 和 TXT 各验证了 75 种写法的实际位图，以及分式样式、箭头伸缩、前向引用、分块边界和源码回退。桌面流程使用模拟 Ollama / OpenAI 兼容服务。实际模型兼容性、通知区域点击、跨显示器 DPI 和屏幕呈现需在相应设备上验证。
